# UX-08 — Multi-interest Journey candidate (27/11/2026)

## Audit and design
- Baseline app 26a70dd LIVE, closure docs c045434. Journey had one legacy slug, 12 stage-guides with 4 existing steps each (48 original keys), homepage one group, legacy-only opt-in history capped at 40 slugs; 219 canonical content refs and 12 lifecycle stages/16 topics now available. No profile, no exact age or medical data.
- Legacy mapping derived from inventory refs originalStage -> canonical stages: five prenatal/pregnancy/postpartum slugs -> prenatal; so-sinh/nhu-nhi -> baby; tap-di -> toddler; mam-non -> preschool; tieu-hoc -> school; thieu-nien -> preteen + teen; truong-thanh -> adult. No invented age inference. Six old homepage groups map using knowledgeGroups; union only when no explicit interestsV3. Lazy read adapter, no writes on migration. Explicit empty array suppresses inherited choices. Legacy stage/homeGroup left intact for rollback; home quick group remains separate UX03 control. 
- Journey: checkbox 0–12, explicit Save/clear, current count and mobile layout; deterministic up to 3 items per selected stage, exact topic filter, diverse topics then inventory order; no behavioral ranking. Existing 48 checklist keys remain unchanged (adolescent checklist shared in preteen/teen). Four new stages without guides show honest empty state, no fabricated tasks/medical schedules. Changing interests never resets checklist. Checklist reset explicitly confirmed.
- History: old historyEnabled true remains legacy-only consent until explicit expanded opt-in; historyAll flag and historyV3 canonical MRU list support all 219 unique IDs, no timestamp or personal profile. Default off; no record unless permitted; old valid history inherited on explicit expansion. Old history bucket retained for rollback until clear; old UI cannot manage expanded bucket. Only dedicated canonical detail reads (legacy URL included) count, not browsing old accordion previews. Explicit opt-out disables flag before deleting both history buckets; failure shown; re-enable from off requires deletion first. Clear history and all data confirmation retained. Clear all includes new keys and legacy keys. Existing bookmark buckets untouched except explicit clear all. 
- Combined DEV SSR only; private catalog metadata rendered behind existing gate; all changes local, no network request on preference/checklist/history mutation; existing non-Combined protected reader behavior unchanged. Homepage retains prior group recommendations and gains expanded recent link and journey summary. Full multi-stage recommendations are on Journey. No content, DB, schema or Production config changes.
